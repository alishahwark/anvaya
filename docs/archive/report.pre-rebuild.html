02

Motivation

Citizens, journalists, students, and civic organizations need to know whether a policy item is proposed, enacted, or still awaiting implementation before assessing implications. Parliamentary records, enacted text, later rules, and commentary often appear in different places and use different language.

Anvaya’s current alternative is intentionally narrow: it presents one local fixture, a timeline, official-source links, and an AI question flow. It does not claim comprehensive Indian legislative coverage.

Status: PARTIAL — user problem is documented; user research and measured task time are not yet available.

03

What Is New

ChatGPT and general search can produce fluent policy explanations, but they do not automatically provide Anvaya’s status/evidence separation or a local, inspectable milestone model. Anvaya’s differentiators are:

  • an explicit distinction between official evidence and AI interpretation;
  • status and milestone fields that can carry verification state;
  • offline fixtures and migrations for reproducible teaching-staff setup;
  • a prompt boundary that treats evidence and questions as untrusted content.

Status: NOT VERIFIED — no comparative user study has established superiority over ChatGPT or search.

04

Agents

The implemented agent is a policy interpreter. It receives a validated question and supplied evidence, calls the configured OpenAI-compatible Responses API, and returns a separately labeled interpretation. With a Portkey key it uses only gpt-6-luna; with a personal OpenAI key it uses OPENAI_MODEL or the documented fallback.

The route records timestamp, provider, model, input tokens, cached input tokens, output tokens, total tokens, duration, and status in an ignored JSONL audit log after a successful API call.

Status: PARTIAL — one real execution was smoke-tested; a screenshot and repeated trace set are not included yet.

05

Tokenomics

The application captures token usage from the API response at data/logs/agent-executions.jsonl. One real smoke execution is preserved in data/benchmarks/agent-trace-2026-10-24.json: 113 input tokens, 0 cached input tokens, 271 output tokens, 384 total tokens, and 2,434 ms duration using Portkey and gpt-6-luna.

This audit does not invent costs: the account’s current Portkey pricing must be recorded before calculating cost. Required calculations are:

  • per run = input tokens × input rate + cached input tokens × cached rate + output tokens × output rate;
  • per user/month = runs per month × per-run cost;
  • 100 and 10,000 users = active users × per-user/month cost.

Status: PARTIAL — one measured trace exists; pricing, repeated workload, scale projections, and quality trade-offs are not verified.

06

Safety

Implemented defenses include Zod length validation, HTTPS-only utility validation, ignored secret files, a provider/model boundary, and prompt instructions that refuse instructions embedded in evidence and prohibit invented legal statuses or sources. The UI labels AI output as interpretation.

The main remaining safety risk is that the current fixture is small and source links are repository landing pages rather than document-level citations. No defense can make that a verified legal database.

Status: PARTIAL — validation and prompt-injection boundaries are implemented and testable; a recorded adversarial test and screenshot are still required.
